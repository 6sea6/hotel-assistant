# 携程采集优化实施与验收记录

日期：2026-09-29。应用版本：8.9.3；采集策略版本：browser-first-v1。

已实现主要源码改动并通过本地回归。本记录不能作为真实携程环境的速度或长期风控保证。严格的“相对实施前当前源码端到端耗时不超过 110%”尚未验收：原始临时基线快照已丢失；本次未访问仍受限制的携程会话。

## 已实现的行为

- 同一受管浏览器资料目录共用访问控制器，暂停原因和冷却截止时间持久化。业务 203、验证页面、HTTP 403、429、登录失效分开处理；HTTP 203 不等于业务反爬码。203 与价格并存也停止后续自动动作。
- 响应到达时检查关键 HTTP 状态，响应体可读时检查业务码。暂停时阻止导航、展开和输入，并尝试终止页面脚本、停止加载；已发请求单独计数。
- 429 尊重完整 Retry-After（秒数或 HTTP 日期），无有效值时采用本地 60 秒保护值。冷却后单个恢复操作试探，失败转人工处理；普通临时故障最多自动重试一次。等待支持取消。
- 正常桌面采集默认 browser_first：监听后导航，复用页面响应；正常批量不启用 Node 房价重放、列表重放、页面内构造请求或移动 HTML 补采。保留显式诊断与离线 HTML 路径。
- 单个共享浏览器最多三个详情标签页；正常并发、三家串行预热和两秒启动间隔保持原设置。共享初始化失败明确失败，不自动复制资料目录启动多个浏览器。
- 同一 CDP 请求的响应体和 JSON 解析复用；以请求 ID 区分同 URL 的不同响应。增量解析放到展开前，仅能证明房型数据完整时提前停止补采；不以找到一个价格作为完成条件。
- 查询在同一任务内合并，键包含日期、人数、房间、筛选和会话代次等条件；不同模板的本地房型筛选分别计算。只缓存完整结果，任务结束清空，新任务/主动更新重新采集。
- 登录恢复要求用户明确确认和页面验证同时通过，关闭窗口不视为成功。任务状态包含暂停和部分完成；界面可恢复暂停任务。
- 进度记录查询摘要、原采集时间和写入标记。恢复时复用完成项，已写入结果不重复写入和计算交通；条件变化拒绝按旧进度恢复，提示作为新任务执行。
- 桌面与 CLI 聚合写入均排除不完整、登录失效和风控结果，保留旧价格。完整的先前结果可以保存。
- 日志提供实际模块路径、应用版本、策略版本和调度参数。任务返回性能字段包括总耗时、活动耗时、人工等待、跨次暂停、冷却、首结果、有效结果、关键业务响应、重复请求、失败分类、暂停/恢复和暂停时在途请求数。桌面总耗时包含清理与写入。

主要代码入口：`scraper/src/ctrip-access-controller.js`、`task-runner.js`、`single-detail-runner.js`、`task-capture-cache.js`、`task-checkpoint.js`、`scraper/ctrip-cdp-guard.js`、`scraper/edge-capture-modules/response-parser.js`，以及 `src/main/ai` 和任务界面状态模块。

## 仍需完成的发布验收

1. 恢复精确的原始完整源码基线，或由维护者明确接受一个重新建立的基线；再做包含真实浏览器/DOM 和写回的固定样本端到端对照。当前无法宣称已达到 10% 目标。
2. 当前限制解除后，以一次正常的 5～10 家任务确认实际页面、登录恢复、最便宜合规房型及保存结果。不要在受限会话上反复跑压力测试。
3. 在实际环境核查日志路径与 `capture:policy` 事件，并观察完整性判定的保守回退比例。不能证明完整时继续补采，不能为缩短时间放宽判定。
4. 暂停后动作指标统计程序发出的受管 CDP 动作；网站自身已在途请求可能仍完成。关键业务计数来自可观察的 CDP 关键响应，不等同于服务端精确计数。暂停状态持久化支持顺序任务与重启，未实现多个独立应用进程同时操作同一资料目录的跨进程锁。
5. 安装包模块校验与离线加载只能证明构建内容及模块可加载；不代表真实网站流程、安装升级或页面布局已验收。

本地验证时保留了既有改动，没有执行线上压力测试。GitHub 预发布分支保存与安装包一致的完整源码快照，包含原有桌面界面、筛选、导出及价格规则更新。
